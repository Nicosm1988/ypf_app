# Registro de maquetado — Maqueta y feedback

> Plantilla mínima reutilizable para la etapa "Maqueta y feedback" (etapa 3 del ciclo canónico de entrega,
> obligatoria y anterior a PRD/Spec). Duplicar por iniciativa y completar antes de redactar PRD/Spec.

| Control     | Valor                              |
| ----------- | ----------------------------------- |
| Etapa       | Maqueta y feedback (previa a PRD/Spec) |
| Ambiente    | Preview local/controlado, no productivo |
| Owner       | Datalización                        |
| Participan  | Cliente/negocio (da feedback y valida dirección) |

## Propósito

Validar comprensión, navegación, jerarquía, acciones y expectativas del cliente antes de comprometer diseño
técnico. La maqueta no es código productivo salvo decisión explícita, y no reemplaza el PRD ni la Spec.

## 1. Objetivo de la maqueta

_Qué decisión o hipótesis de usuario se quiere validar con esta maqueta._

## 2. Usuario/decisión

_Quién usa la maqueta y qué decisión debe habilitar la solución final._

## 3. Escenarios representados

_Lista de escenarios o pantallas cubiertos por la maqueta._

## 4. Supuestos

_Supuestos funcionales o técnicos asumidos para construir la maqueta._

## 5. Datos ficticios usados

_Descripción de los datos sintéticos o anonimizados utilizados. Nunca datos internos sensibles, credenciales
ni endpoints reales._

## 6. Enlace o archivo

_URL o archivo versionado de la maqueta (preview local/controlado)._

## 7. Rondas de feedback

_Fecha, participantes y síntesis de cada ronda de feedback con el cliente._

## 8. Decisiones tomadas

_Decisiones de dirección resueltas durante el feedback._

## 9. Cambios pedidos

_Cambios solicitados por el cliente que impactan la maqueta o el futuro PRD/Spec._

## 10. Pendientes

_Puntos abiertos que deben resolverse antes de avanzar a PRD/Spec._

## 11. Aprobación de dirección

_Quién aprobó la dirección de solución, con fecha, para habilitar el paso a PRD/Spec._

## 12. Impacto en PRD/Spec

_Qué decisiones de esta maqueta deben incorporarse literalmente en el PRD y en la Spec._

## Controles obligatorios

- Banner "Maqueta — no productiva" visible en la maqueta.
- Datos ficticios, nunca reales.
- Versión, fecha y owner visibles.
- Link a este registro de feedback.

## Criterio de salida

El cliente comprende el flujo propuesto, las decisiones principales de dirección están resueltas y existe
información suficiente en este registro para redactar PRD/Spec.
